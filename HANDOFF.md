## 3. Известные ограничения и риски

### Контент
1. **Контент написан AI и не вычитан преподавателем.** Рассказы, 40 тем грамматики (592 упражнения), тесты и переводы словарей
   проверены автоматически (формат, «правильный ответ действительно засчитывается»), но **не человеком-экспертом**.
   Возможны: неточный перевод, неоднозначный вопрос (два ответа подходят), неестественная фраза.
   → Если встретите ошибку — исправьте JSON/CSV и запустите `validate_content.py` + `build_site_data.py`. Желательно выборочно показать преподавателю B1-темы.
2. **Подсветка слов — автоматическая.** Слово, совпадающее со словарным по форме, отмечается всегда, даже если в тексте другое значение.
   Поэтому показываются **все** значения формы. Имя в начале предложения (*Mark went…*) может отметиться как слово *mark*.
3. **Задание «вставьте слово»** собирается автоматически: иногда неправильный вариант тоже может грамматически подойти.
4. **Рассказы 21–40 без mp3** (так решили): читает голос браузера, его качество зависит от устройства.

### Диктант
- Цифры и слова считаются одинаковыми (`25` = `twenty-five`), но:
  - годы читаются как числа: `1999` = «one thousand nine hundred ninety nine», а не «nineteen ninety-nine»;
  - порядковые (`25th`), сокращения (`it's` ≠ `it is`), британское/американское написание (`colour` ≠ `color`) считаются ошибкой.

### Прогресс
- **Прогресс хранится в браузере и привязан к адресу сайта.** `localhost:5173`, `192.168.1.5:5173` и `172.20.10.2:5173` — для браузера
  **три разных сайта** с разным прогрессом. Если у компьютера в сети сменится IP (другой Wi-Fi, точка доступа), на телефоне прогресс «пропадёт»
  (он останется по старому адресу). **Решение:** резервная копия в файл — сохраните на старом адресе, загрузите на новом. После деплоя адрес станет постоянным.
- В списке слов статус меняется кнопками «учу» / «выучено» (в фильтрах «Новые», «Учу», «Выучено»); история повторений при этом **не удаляется**.
  Вернуть слово в «новое» из интерфейса нельзя (и не нужно).
- Очистка данных браузера удаляет весь прогресс — делайте резервную копию в файл время от времени (автоматической нет).

### Техника
- **Данные сайта (`web/public/data`) лежат в git и генерируются.** Если изменить контент и забыть `build_site_data.py`, сайт покажет старые данные.
  CI пересобирает данные перед тестами, но **не проверяет**, что в репозитории они актуальны. → Совет 9.
- **Тесты в браузере завязаны на контент** (например: в A2 ровно 906 слов, первое предложение диктанта рассказа 01 — «Anna is twenty-five years old»).
  Если изменить эти данные, тесты упадут — это нормально, их нужно обновить вместе с контентом.
- **edge-tts** (озвучка) — неофициальный доступ к голосам Microsoft. Может перестать работать без предупреждения; готовые mp3 это не затронет.
- **`npm audit`**: уязвимость `picomatch` (ReDoS) в инструментах сборки, на сайт не попадает, исправления пока нет. Остальное устранено.
- **mp3 больше не в git** (с 2026-11-20 — Supabase Storage). Старые коммиты всё ещё содержат ≈ 115 МБ; уменьшить — только переписав историю (не делали).
- **Supabase Free:** трафик 5 ГБ/мес; проект засыпает после недели без активности → mp3 на сайте перестанут играть (рассказы перейдут на голос браузера). Против этого — `keep-supabase-awake.yml`.
- **Новые mp3 не попадут на сайт сами:** после `make_story_audio.py` / `make_word_audio.py` — `build_site_data.py` и `upload_audio.py`. Если забыть загрузку, плеер будет пустым (`build_site_data.py` предупредит «⚠ Нет mp3», только если mp3 нет на диске).
- **Ключи AI** — в секретах Worker'а, браузер их не видит; `/api/ai` работает только после входа по коду.
  Свои ключи в браузере остались запасным вариантом (они видны в инструментах разработчика).
  Не вписывать ключ в код и в `.env` сайта — после сборки он окажется в открытых файлах сайта.
- **Ключ Gemini и код доступа попали в чат с Claude (2026-11-19)** — пользователю: создать новый ключ Gemini, удалить старый; сменить код в `ACCESS_CODES`. Ключ Groq, засветившийся раньше, тоже заменить, если это не сделано.
- **Секреты — только через обычный Терминал**: `npx wrangler secret put ИМЯ` ждёт ввода, через `!` в чате с Claude значение не передаётся (так в секрете оказался неверный ключ Groq). Проверить, какие секреты есть: `npx wrangler secret list` (только имена).
- **Бесплатный Gemini нестабилен**: модели бывают перегружены (503) или «зависают»; при смене моделей Google проверить `…/api/ai/check` и при необходимости задать `GEMINI_MODEL`.
- **Лимита AI на человека пока нет** (будет с D1): вошедший по коду может делать запросы без ограничений в пределах лимитов Gemini/Groq. То же для озвучки `/api/tts`.
- **Озвучка edge-tts в Worker'е — неофициальный доступ, и его придётся поддерживать.** Microsoft периодически меняет токен `Sec-MS-GEC`
  (в 2026 перешёл на v2 — запутанный хеш). Тогда `/api/tts` начнёт отвечать «Сервис озвучки не принял соединение (HTTP 403)».
  Как чинить: `pip install -U edge-tts` → перенести изменения `edge_tts/drm.py` и `constants.py` в `web/worker/edgeTts/drm.ts`
  (константы генерируются скриптом — см. шапку файла) → обновить эталоны в `drm.test.ts`. Готовые mp3 на устройствах это не затрагивает.
- **mp3 «Моих слов» не входят в резервную копию** (только слова): после очистки браузера их нужно пересоздать кнопкой.
- **Сам сайт открыт всем** (уроки, mp3) — закрыты кодом только AI и (в будущем) прогресс.

### План: аккаунты + база прогресса в Supabase Postgres (решено 2026-11-20, не начато)
**Решения пользователя (2026-11-20):**
- База — в том же Supabase (не D1); когда-нибудь может смениться, но не скоро. Структура базы будет **много раз меняться** до завершения.
- Сайтом пользуются **гость** или **вошедший пользователь** (username + пароль). **username уникальный, с учётом регистра:** `Rasul` ≠ `rasul` (это два разных имени).
- **Аккаунты создаёт только админ** (саморегистрации нет). Пароль забыт — новый задаёт админ (email нет).
- **Гость может всё, прогресс — только в его браузере, как сейчас.** **AI у гостя — как сейчас: только свой ключ в браузере** («Свои ключи»);
  общий ключ сайта гостю не даётся.
- **AI у пользователя — свой ключ или ключ от админа:** пользователь **сам вписывает свой ключ в профиле** (`#/profile`); или админ в админ-панели вписывает ему **отдельный новый ключ** (Gemini/Groq),
  либо включает **общий ключ** (свой, `GEMINI_API_KEY`/`GROQ_API_KEY` в секретах Worker'а). Ключи пользователя хранятся в базе
  **зашифрованными** (AES-GCM, ключ шифрования — секрет Worker'а `KEYS_SECRET`), браузер их не видит.
  **Пароль — хеш** (только проверить), **AI-ключ — шифрование** (его надо расшифровать, чтобы отправить в Gemini/Groq; хеш необратим).
  Ключ пользователя **в браузер не возвращается**: AI-запрос идёт через Worker, который берёт ключ из базы. Очистка localStorage
  или новое устройство ничего не теряют — после входа AI сразу работает. В профиле/админке видно только «ключ есть, …a1B9».
  Ключ гостя — только в его localStorage (потерял — ввести заново).
- **Лимит AI-тестов: 5 в день на пользователя**, размер теста — как сейчас (~19 вопросов: 8/6/5) → до ~95 вопросов в день.
- **Лимит озвучки** (`/api/tts`, 1 слово = 1 запрос; уже озвученные слова не запрашиваются): **пользователь — 300 слов в день, гость — 50 слов в день**
  (гость считается по хешу IP — сам IP не хранится).
- **Вход помнится 30 дней** (потом снова username + пароль).
- Конфликт телефон ↔ компьютер: **последнее изменение побеждает** (по каждой строке).
- **Вход — свой, в Worker'е** (не Supabase Auth: тот требует email). Коды доступа `ACCESS_CODES` уходят.
- **Админ-панель**: пользователи — создать, изменить username, задать новый пароль (с повтором пароля), удалить.

**Как устроено:**
```
браузер ──/api/*──▶ Worker: вход, сессии, роли, лимиты ──REST, секретный ключ──▶ Supabase Postgres
   └─ localStorage — рабочая копия прогресса: сайт работает без сети, изменения уходят на сервер пачками
```
- Браузер **не ходит в Supabase напрямую**. Секреты Worker'а: `SUPABASE_URL`, `SUPABASE_SECRET_KEY`.
- **RLS включён на всех таблицах, политик нет** → публичный ключ Supabase не прочитает ничего.
- Пароль хранится только как хеш **PBKDF2-SHA256** (WebCrypto в Worker'е, своя соль у каждого). Сессия — случайный токен в HttpOnly-cookie,
  в базе — только его хеш; выход и смена пароля админом закрывают сессии. Неудачные входы ограничены (5 попыток → пауза).
- Прогресс привязан к `user_id`, а не к имени → смена username ничего не ломает; удаление пользователя удаляет и его прогресс (`on delete cascade`).
- Дни — как сейчас, номером дня (`dayNumber`); время — `timestamptz`. У каждой строки `updated_at`: при расхождении устройств побеждает более новая строка.

**Профиль пользователя** (`#/profile`, после входа):

**Админ-панель** (`#/admin`, видна только `role = admin`; каждое действие Worker проверяет заново):
- список: username, роль, дата создания, последний вход;

- AI пользователя: Gemini / Groq — «отдельный ключ» (вписать; видны только последние 4 символа) или «общий ключ сайта», или выключено;
- удалить — с подтверждением («удалить? прогресс тоже удалится»). Нельзя удалить себя и последнего админа.
- **Первый админ:** скрипт `tools/create_user.ts` (`--user` — обычный пользователь) спрашивает username и пароль и печатает SQL (с хешем, не с паролем) → вставить в SQL Editor.

**Изменения структуры базы без потери данных** (структура будет меняться много раз):
1. **Миграции — SQL-файлы в git:** `supabase/migrations/<ГГГГММДДччммсс>_<имя>.sql` (так требует Supabase CLI; порядок — по времени в имени). Каждое изменение — новый файл,
   старые не правятся. Применяет **Supabase CLI** (`npx supabase db push --remote`; таблица применённых миграций ведётся сама) — одна команда из Терминала.
2. **Только «расширить → перенести → убрать»:** новый столбец — с `default` или `null`; переименование = новый столбец + копирование данных +
   код читает новый; старый столбец удаляется отдельной миграцией позже, когда код на сайте уже обновлён. `drop` / `rename` за один шаг — нельзя.
3. **Перед каждой миграцией — копия данных:** `npx supabase db dump --remote --data-only -f backups/<дата>.sql` (без `--remote` CLI 3.x идёт в локальную базу) (папка в `.gitignore`).
4. **Сначала на тестовом проекте:** у Supabase Free 2 проекта → второй, «тестовый», для ветки `development`; миграция проверяется там, потом — на основном.
5. **Гибкое поле `extra jsonb`** в таблицах: новое экспериментальное поле можно хранить там без миграции; когда устоится — сделать столбцом.
6. Worker выбирает **явный список столбцов** (не `select *`) и не падает, если в строке есть лишние поля → старый код переживает новые столбцы.
7. Тесты Worker'а для API — на подставном Supabase; SQL миграций проверяется применением к тестовому проекту.

## 6. Рекомендуемый режим занятий (30–40 минут в день)

| Время | Что | Где на сайте |
|---|---|---|
| 10 мин | повторение слов + 10 новых | Сегодня → Слова |
| 10–15 мин | рассказ: послушать с караоке, прочитать, задания; раз в неделю — диктант | Рассказы |

| по желанию | mp3 со словами (в дороге), 10 глаголов | Аудио / Практика |
| раз в 1–2 месяца | пробный экзамен B1 или новый тест от AI | Практика → Тесты |

Ориентиры на год: месяцы 1–3 — рассказы 01–20 и грамматика A2; 4–9 — рассказы 21–40 и грамматика B1; 10–12 — пробные экзамены,
письмо и говорение. Плюс живая разговорная практика и с середины года — подкасты/сериалы с английскими субтитрами.
